# BYOAI 스마트홈 — 온디바이스 LLM 실증 + 시뮬레이션

> **목표**: 사용자가 자기 AI(폰)를 들고 *어느 공간에 가든* 그 공간을 파악해
> 본인에게 최적화되게(특히 난방 온도) 동작시키는 스마트홈.
> 폰 = 두뇌(결정), 라즈베리파이 = 척수(실행), 휴대용 사용자모델 = 기억.

---

## 1. 아키텍처 (연합 구조 · 신경계 비유)

| 역할 | 구현체 | 책임 |
|------|--------|------|
| **대뇌** | 폰의 on-device Gemma 4 | 공간 descriptor + 내 선호를 결합해 목표온도 "결정"만 |
| **척수** | 공간의 라즈베리파이 (항상 켜짐) | 기기·열모델 발행, 제어루프(목표 유지), 센서 |
| **기억** | 휴대용 사용자모델 (폰에 들고 다님) | 수동보정을 누적 학습 → 공간 옮길수록 똑똑해지는 복리 |
| **신체** | 실제 공간/기기 (시뮬은 RC 열모델) | 물리 열역학 |

**왜 LLM인가**: 임의 공간 = 기기 구성을 미리 모름 → 런타임에 처음 보는 구성 보고
즉석 추론 필요 → 하드코딩 불가. **방 크기·열특성 유추는 공간(척수)의 책임**(열응답
자가학습), 폰은 읽기만 → 환각 방지.

**학습 신호 = 수동 제어**: 시스템 25도 → 사용자가 26도로 올림 = "정답은 26도"라는
암묵적 피드백. (맥락피처 + 보정값) 쌍으로 휴대용 사용자모델에 누적.

## 2. 온디바이스 LLM 실측 (갤럭시 S22 울트라)

**환경**: SM-S908N, 스냅드래곤 8 Gen 1, 12GB RAM, Android 16, llama.cpp b9442, ADB.

### 속도 (tok/s, CPU 4스레드 = 최적)

| 모델 | 양자화 | 크기 | 프롬프트 | 생성 |
|------|--------|------|---------|------|
| Gemma 4 **E4B** | Q4_K_M | 4.95 GiB | ~21 | **5.5** |
| Gemma 4 **E2B** | Q4_K_M | 2.96 GiB | ~48 | **12.8** |

- **4스레드 초과는 더 느려짐**: 작은 코어(A510) 경합 + 생성은 메모리대역폭 바운드라
  코어 늘려도 안 빨라짐.
- **GPU(Adreno 730 OpenCL)는 오히려 느림** (생성 1.39 tok/s): OpenCL 백엔드는
  8 Gen 2+ 튜닝 → 8 Gen 1에선 막다른 길. CPU가 정답.

### 결정 품질 (동일 BYOAI 프롬프트: 카페·비 맞고 들어온 추위민감 사용자)

| 모델 | 목표온도 | preheat | 추론 |
|------|---------|---------|------|
| **E4B** | **23.0도** | 15분 | 쾌적기준선 + 민감도 + **과거 비보정 이력**까지 통합 |
| **E2B** | 21.5도 | 15분 | "현재 19.5 + 2도" 식 단순 가산, 과거 신호 누락 |

> **결론**: 속도는 E2B로 충분하지만 추론 깊이는 E4B 우위. 온도결정은 즉시성이
> 필요 없으므로 **E4B 채택**. (제어루프·열모델 학습은 LLM이 아니라 라파이 통계코드.)

## 3. End-to-End 시뮬레이션 (`byoai_sim.py`)

폰의 **진짜 Gemma 4를 adb로 호출**해 결정을 받고, 파이썬 RC 열모델로 공간 물리를
돌린다. 모델 미가용 시 heuristic 폴백.

**시연 흐름**:
1. 공간 A(카페, 외풍) 진입 → 대뇌가 목표온도 결정 → 척수 제어루프가 가열
2. 사용자 수동보정(+1도) → 휴대용 사용자모델 학습 (오프셋 +2.0 → +2.5)
3. 전혀 다른 공간 B(친구집, 단열 좋음) 진입 → 학습된 선호로 더 정확한 초기 결정

```bash
adb devices                       # 폰 연결 확인 (device 상태)
python byoai_sim.py               # 폰 Gemma로 end-to-end 실행
```

### 실행 결과

실제 폰 Gemma 4 **E4B**가 두 공간에서 내린 결정 (2026-06-01, S22 울트라 adb):

**① 공간 A — 카페 거실존** (현재 19.5도 / 외부 2도 / 비 맞고 진입)
```
[대뇌·E4B] 목표 23.5도 / 예열 15분
  이유: "비에 젖어 들어온 사용자의 체감 온도를 고려하여 평소 선호도보다
        높게 설정하고, 빠른 쾌적함 회복을 위해 예열을 진행합니다."
[척수] 제어루프 가열 → t+18분 목표 도달
[수동보정] 사용자가 23.5 → 26.0도 손수 올림
[학습] 휴대용 선호 오프셋 +2.0 → +2.5 (보정기록 1건 누적)
```

**② 공간 B — 친구집 작은방** (전혀 다른 공간, 학습 직후)
```
[대뇌·E4B] 목표 22.5도 / 예열 0분
  이유: "사용자가 추위를 느끼는 경향이 있고 ... 평소보다 2.5도 높은
        온도로 설정하는 것이 적절합니다."   ← 방금 학습한 +2.5를 그대로 반영!
[척수] 제어루프 가열 → t+9분 목표 도달
```

> **핵심 증명**: 공간 A의 수동보정으로 학습한 `+2.5` 오프셋이, 전혀 다른 공간 B의
> 초기 결정 근거에 **"평소보다 2.5도 높은"** 으로 그대로 나타났다. = 내 AI를 들고
> 다닐수록 공간 불문 똑똑해지는 **BYOAI 복리효과**의 실측 시연.

**구현 노트 (재현성)**: 대화모드 `llama-cli`(b9442)는 `-f` 프롬프트 생성 후 stdin을
기다린다. `< /dev/null`로 EOF를 주면 빈 `> ` 프롬프트를 무한 출력(307MB까지 관측)하며
종료하지 않는다. **stdin으로 `/exit`를 보내 생성 직후 깔끔히 종료**시키는 게 정답
(device-side `timeout`을 백스톱으로 둠).

## 4. 미해결 핵심 난제

1. **능력 발견 표준**: 공간이 열모델+사용자선호 이식을 표준 형식으로 발행해야 함
   (Matter엔 없음 → 직접 정의). 본 PoC의 `SPACE_DESCRIPTOR` JSON이 그 초안.
2. **신뢰/권한 scoping**: 남의 폰이 공간 제어 → 게스트 권한 제한, 공간 주인 정책 우선.
3. **다중 사용자 선호 충돌** 해소.
